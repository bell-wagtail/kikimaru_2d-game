# 変更後の検証

前提：[環境準備](SETUP.md)が完了していること。検証結果はここに蓄積せず、[STATUS](STATUS.md)に記録します。

## 自動検証

プロジェクトルートで実行します。コマンド定義は [package.json](../package.json) の `scripts` が正本です。

```powershell
mise exec -- npm.cmd --cache .npm-cache run check
mise exec -- npm.cmd --cache .npm-cache test
mise exec -- npm.cmd --cache .npm-cache run build
```

- `check`：TypeScriptの型チェック。
- `test`：入力・移動・背景の反復位置・座標補正・障害物定義と接触・文字マップの変換・穴と床区間・床の着地条件・入力検証。ブラウザ描画やPhaserの実際の物理動作を保証するテストではありません。
- `build`：型チェックを含む配信用ファイルの生成。出力先・消去方針は [vite.config.js](../vite.config.js) を参照。

変更内容に必要な検証だけを選びます。`build`を実行する場合、直前の`check`は省略できます。
Phaserのチャンクサイズ警告が出る場合は、ビルドの終了結果と区別して扱ってください。
現在は出力先を自動消去しない設定なので、公開前には古い生成ファイルの扱いを確認します。

## 手動確認

[起動・操作手順](RUN.md)に従ってデモを起動し、変更の影響がある項目を確認します。

- 左右移動・キーを離したときの停止・左右同時押し・画面端に相当する距離を越えても移動を続けられること。
- 背景と地面の反復境界に隙間が出ず、折り返しや長距離移動で背景・キャラクターが急に飛ばないこと。
- 地上からのジャンプ、着地、移動しながらのジャンプ。
- 左右どちらのShiftでも徐々に加速し、離すと徐々に徒歩速度に戻ること。減速途中の再押下で残った速度から加速すること。Shift単独では助走をためられず、地上で左右入力を解除・相殺すると停止して助走がリセットされること。
- 徒歩ジャンプ中にShiftを押しても加速せず、ダッシュジャンプ中に離しても減速しないこと。加速途中・減速途中のジャンプも踏み切り速度を保ち、着地から現在のShift状態に応じて加減速を再開すること。高さ・滞空時間が変わらず、飛距離だけが踏み切り速度に応じて伸び、背景が飛ばないこと。
- ダッシュ中のリセット・フォーカス喪失後に加速状態が残らないこと。
- 徒歩・加速途中・最高速度のそれぞれで、岩の左右の側面に当たると停止し、押し続けてもめり込まないこと。逆方向へ離れられること。
- 岩上への着地・静止・再ジャンプ・端からの落下・飛び越え。壁際からジャンプすると岩より高くなった時点で横に進めること。
- 文字マップの配置に従い、低い岩から中段・上段へジャンプで登れること。横に並ぶ岩の継ぎ目で停止・落下しないこと。マス寸法を変えると位置・表示・当たり判定が一緒に変わること。
- `o` のお茶に衝突・取得効果がなく、座標補正・リセットでも岩に対する配置位置が変わらないこと。
- 座標補正後も岩の表示と衝突位置が一致し、戻ってきた際に同じ場所で衝突すること。空中・岩上・座標補正後のリセットでプレイヤーと岩が開始位置へ戻ること。
- 最下行の空きマスが草・土・根のある穴になり、徒歩・加速途中・最高速度で左右から落下でき、ジャンプで対岸へ着地できること。落下中に左右の壁へ当たると横移動だけが止まり、押し続けても床の下へ抜けず、下へ落ち続けること。反対方向へ壁から離れられ、床面へ持ち上がらず空中ジャンプもできないこと。画面下への落下と落下途中のリセットで、位置・入力・助走・背景・カメラが開始状態に戻ること。
- 穴の上の岩にも着地・再ジャンプできること。座標補正後も穴の表示・床の衝突位置が一致し、穴に再訪しても落下・リスポーンできること。
- 押しっぱなしで自動連続ジャンプしないこと、空中で再ジャンプしないこと。
- 「まんなかに戻る」で背景・地面・カメラも戻ることと、別タブ・別ウィンドウへ移った際の入力解除。
- タッチ対応を変更した場合は、移動とジャンプの同時操作をスマホ実機で確認。

## Phaser上の横スクロール結合テスト

通常移動に加え、Shift入力による連続加減速・減速途中の再加速・左右Shift併用・踏み切り時の速度維持・着地後の加減速・高さと滞空時間の一致・飛距離の速度比例・状態表示と、ダッシュでの長距離移動・座標補正・フォーカス喪失・リセットも検証します。

[obstacles.browser.js](../tests/obstacles.browser.js) の障害物検証も同じページから実行します。徒歩・加速途中・最高速度で左右からの側面停止、岩上の着地・静止・再ジャンプ・歩いて降りる動作、飛び越えを確認します。左右の座標補正境界に岩を置くステージへ再起動し、空中での補正から岩上へ着地、補正後の衝突、複数補正後の再訪、物理ボディと衝突検索位置の一致、各状態でのリセット、再起動時の重複がないことも確認します。背景の長距離検証は障害物のないステージで行います。

[stageMap.browser.js](../tests/stageMap.browser.js) は [専用の階段マップ](../tests/fixtures/stairs.txt) から生成したステージを検証します。開始位置からの歩行→低い岩→中段→横5個の上段への連続ジャンプ、上段の左右歩行、tea仮表示、左右の座標補正とリセット、マス寸法変更、再起動時の重複を確認します。実際のステージを編集しても、この回帰テストの配置は変わりません。

[ground.browser.js](../tests/ground.browser.js) は穴のあるテストステージを検証します。徒歩・加速途中・最高速度で左右から落下して壁へ衝突・停止を維持し、下へ落ちてリスポーンする動作、穴の中で方向転換して両方の壁で停止、ジャンプで対岸へ着地、入力と助走の解除、落下中の空中ジャンプ拒否・手動リセット、体幅より狭い穴の通過、穴を広げても縁の素材の大きさと壁の物理境界を保つこと、穴の上の岩への着地・再ジャンプ、左右の座標補正と複数補正後の再訪、床の衝突検索位置、リスポーン・再起動時のオブジェクト数を確認します。

[RUN](RUN.md)に従って開発サーバーを起動し、表示されたURLのパスを `/@fs/<プロジェクトの絶対パス>/tests/scrolling.browser.html` にします。Windowsのパス区切りは `/` を使用します。このページは開発サーバー専用で、配信用ビルドには含みません。

「結合テストを実行」で現行の `WalkScene` を使い、左右の長距離移動、空中での座標補正、着地、停止、フォーカス喪失、リセット、別ステージ定義での再起動を検証します。結果の最終行が `PASS 全項目完了` になることを確認してください。URL末尾に `?canvas` を付けるとCanvas描画、それ以外はWebGL描画です。

「右へ4秒進める」「左へ4秒進める」で移動後の反復境界、「穴の手前を表示」で現行ステージの最初の穴を目視できます。テストは物理更新を高速に進めるため、実時間の長時間プレイや端末性能の測定ではありません。

## 配信用ビルドの表示

ビルド結果を確認するときは、`build`の成功後に次を実行し、表示されるURLを開きます。これは公開操作ではありません。

```powershell
mise exec -- npm.cmd --cache .npm-cache run preview
```
