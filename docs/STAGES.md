# 文字マップでステージの配置を編集する

配置の正本は [src/stage-maps/](../src/stage-maps/)、マスの大きさ・原点・ステージとマップの対応は [stages.ts](../src/stages.ts) です。通常起動はユーザー編集済みの [tea-river.txt](../src/stage-maps/tea-river.txt) を読み込みます。寄り道を試す別ステージは [tea-river-trail.txt](../src/stage-maps/tea-river-trail.txt) です。

## 寄り道ステージ

`STAGES.teaRiverTrail` に、お茶で走る区間・えびで登る高台・穴の上の低い橋を配置しています。地上の果物を集めながら進むルートと、2段ジャンプで高台の魚・いちごを集める寄り道を選べます。高台の下には歩ける空間があり、登らなくても先へ進めます。クイズは序盤・中盤・終盤の平地に分散し、高台から降りた後にも着地できる距離を空けています。序盤の空きマスにスタート、終盤の広い平地にゴールを指定しています。

マス設定の正本は `TRAIL_MAP_GRID`。高台へ2段ジャンプで届き、下を歩ける高さに合わせています。[CHECKS](CHECKS.md) の開発用ページで「寄り道ステージで遊ぶ」を押すと開始位置から、「高台の手前から遊ぶ」ではえびの手前から試せます。手動リセットではどちらもステージの開始位置へ戻ります。通常起動の `DEFAULT_STAGE` と元のマップは維持しています。

## 記号と位置

| 記号 | 配置 |
|---|---|
| `.` または半角空白 | 最下行では穴。それより上の行では何も置かない |
| `x` | 岩1個。表示・矩形当たり判定は1マス分 |
| `o` | お茶。効果中は地上移動がShiftなしで即最高速度 |
| `j` | えび。取得すると空中で追加1回ジャンプ |
| `F` | 魚。能力なしで種類に応じた点数を獲得 |
| `M` | みかん。能力なしで種類に応じた点数を獲得 |
| `S` | いちご。能力なしで種類に応じた点数を獲得 |
| `Q` | クイズマーカー。接触で4択クイズを表示 |
| `I` | スタート。横はマス中央、足元はマス下端 |
| `G` | ゴール旗。横はマス中央、足元はマス下端。表示矩形への接触で結果を確定 |
| `L` | 左壁。このマスの右端から右側へ移動できる |
| `R` | 右壁。このマスの左端から左側へ移動できる |
| `=` | 床。最下行にだけ指定 |

`xxxxx` は5個の岩です。ひとつの画像やボディには結合しません。上の行に置くほど高い位置になり、同じ行の岩は上面の高さがそろいます。空中に置いた岩も固定され、落下しません。

マップは長方形にし、全行の文字数をそろえてください。最下行は床の `=` と穴の `.` / 半角空白で指定します。行を伸ばす場合は、ほかの行にも `.`、最下行にも床か穴の記号を追加します。前後の空行、UTF-8のBOM、Windowsの改行に対応しています。行の途中の空行や未対応の記号はエラーになります。

例えば、最下行を `===...===` にすると、床の間に3マス分の穴ができます。連続する空きマスをひとつの穴として扱います。穴の幅はマス幅に連動し、深さは画面下までです。[groundTextures.ts](../src/groundTextures.ts) で元の地面と同じ色・草の帯・少量の模様を使った縁と土壁を描き、穴の内側へ暗くします。穴を広げると中央部分だけが伸び、左右の土壁は同じ厚さを保ちます。非常に狭い穴では土壁を縮めて収め、穴の外側の地面へはみ出しません。岩を穴の上へ置くこともでき、その岩は固定足場になります。

足元の矩形当たり判定が床から完全に離れると落下します。キャラクターの当たり判定幅より狭い穴はまたげるため、現在のマス設定で落下する穴にする場合は `..` 以上を使ってください。幅を変えた場合は [movement.ts](../src/movement.ts) の `PLAYER.width` と [stages.ts](../src/stages.ts) のマス幅の関係を確認します。飛び越えられる幅は踏切位置・速度にも依存します。

落下中に穴の左右の壁へ当たると横移動が止まり、下へ落ち続けます。押し続けても床の下へ抜けず、反対方向へ離れられます。壁に当たっても床面へ持ち上がりません。えびの効果がある間は落下中も空中ジャンプを1回使えます。画面下へ落ち切ると開始位置へリスポーンし、入力・助走・背景・カメラも開始状態へ戻ります。能力を解除して全アイテムを復元します。リスポーンは `I` の位置と高さへ戻り、短い開始演出の後に自動再開します。`I` 未指定なら従来の開始位置へ即復帰します。GameOver・残機はありません。

マップの左右端そのものは移動の端にならず、マップの外側には床が続きます。`L/R` を置くとその位置で移動を制限します。岩・穴・アイテム・スタート・ゴール・壁の配置は横方向へ反復しません。

### 左右の壁

`L`（左壁）と `R`（右壁）を、最下行以外の空きマスへ配置します。指定するのは列で、行の高さに関係なく画面上端から落下中まで横移動を止めます。`L` のマスは境界の左外側、`R` のマスは右外側です。マス寸法・原点の変更に追従します。

```text
L..I.......G..R
===============
```

各記号は最大1個です。片側だけの指定もでき、未指定側は従来どおり自由に移動できます。両方置く場合は `L` を `R` より左に置き、内側にキャラクターの身体幅以上の間隔を確保します。スタートとゴールは身体全体が境界内に収まり、全アイテム・クイズも内側に配置してください。違反すると行・列付きの壁位置を含むエラーになり、取得できない配置を満点へ含めたままプレイすることを防ぎます。`I` 未指定の場合も従来の開始位置が境界内に入る必要があります。

壁には薄い縦の点線、短い柱と「ここまで」を表示します。徒歩・ダッシュ・能力中・ジャンプでも通り抜けず、押し続けても横移動を停止し、逆方向には離れられます。壁際でも落下・リスポーンは維持します。座標補正に表示と物理境界が参加し、開始・各リセットで指定位置へ復元します。

現行マップと寄り道マップには、スタート・ゴールの外側の空きマスに `L/R` を追加しています。既存の記号は動かしていません。配置位置はMAPで変更できます。座標指定ステージでは `StageDefinition.walls` の `left` / `right` に境界の座標を指定します。記号・配置検証は [walls.ts](../src/walls.ts)、表示・物理境界・補正は [StageWalls.ts](../src/StageWalls.ts) が正本です。

### スタートとゴール

`I` と `G` はそれぞれ最大1個です。最下行には置けません。マス幅・高さ・原点の変更に追従し、横位置はマス中央、足元はマス下端になります。足元でキャラクターの物理幅全体を支える床、または同じ高さの連続した岩上面が必要です。身体が岩や画面上端に重なる配置、床不足、複数指定は行・列付きエラーです。岩上に置く場合は、身体の高さに十分な空き行も確保してください。

`I` を省略すると従来の開始位置と即開始を維持します。`G` を省略すると自由に歩き続けられます。明示的な開始位置では開始・手動リセット・再挑戦・再起動時に開始操作を待ち、落下リスポーンでは短い演出後に自動再開します。操作は [RUN](RUN.md) を参照してください。

ゴール旗はマス寸法に応じて縦横比を保って表示し、その表示矩形で接触を判定します。表示倍率の正本は [stageEndpoints.ts](../src/stageEndpoints.ts) の `MILESTONE_FEEDBACK` です。スタートとゴールも累積の座標補正へ参加します。定義位置は変更せず、リセット時に指定スタートを基準として補正し直すため、大きな原点や負の座標でも表示・接触・復元がそろいます。

満点は配置した全アイテムの配点と、全 `Q` を正解した場合の加点を合計します。同種アイテムも配置数分、クイズが複数巡に入ってもマーカー数分数えます。スコアの下限は維持し、上限はこの満点です。配点の正本は [score.ts](../src/score.ts)。アイテム・クイズがないマップも使え、結果は `0 / 0点`・`0 / 0問`・未回答なしとなります。

## 編集する

1. 対象の文字マップをテキストエディターで開き、上の行の `.` を `x` / `o` / `j` / `F` / `M` / `S` / `Q` / `I` / `G` に置き換えたり、最下行の `=` を `.` に置き換えたりして保存します。等幅フォントだと位置を見比べやすくなります。
2. [RUN](RUN.md) の手順で開いた画面を確認します。開発サーバーでは保存したマップが反映され、シーンは開始位置へ戻ります。
3. ジャンプで次の段に届くこと、上面へ着地すること、岩の側面・継ぎ目や穴で意図した動作になることを確認します。検証手順は [CHECKS](CHECKS.md) を参照してください。

マスの幅・高さを変える場合は、`stages.ts` の対象ステージの設定（`STAGE_MAP_GRID` / `TRAIL_MAP_GRID`）の `cellWidth` / `cellHeight` を編集します。岩の位置・表示寸法・当たり判定、アイテムの配置と表示枠、穴の位置・幅、スタートとゴールの位置・旗の表示と接触矩形が一緒に変わります。アイテムは表示枠内に縦横比を保って収め、実際の表示矩形とプレイヤーの物理矩形が重なると取得します。横方向の原点は `originX`、地面の基準は `groundY` です。ゲームの床の高さは `WORLD.ground` なので、ステージの `groundY` もそれを指定してください。

マスを大きくすると段差や距離も広がるため、変更後は改めてジャンプで届くか確認します。ジャンプの高さや速度の設定を、配置変更に合わせて自動で変えることはありません。

## 別のステージを作る

`src/stage-maps/` に別の `.txt` を保存し、`stages.ts` から `?raw` 付きで読み込みます。ステージ定義に `...parseStageMap(読み込んだ文字列, 設定)` を指定すると、`obstacles` / `items` / `holes` と、指定した場合の `start` / `goal` / `walls` が生成されます。ステージごとに設定を変える場合は、`{ ...STAGE_MAP_GRID, cellWidth: 希望の幅, cellHeight: 希望の高さ }` のように渡します。

座標指定の `start` / `goal` も `{ x, y, width, height }` で任意に指定できます。文字マップと同じく矩形の中央X・下端Yを位置とし、足場と身体の検証も行います。省略した既存の座標ステージはそのまま使えます。

座標指定による `obstacles` / `items` 配列も使えます。アイテムには `{ id, kind: "tea" / "shrimp" / "fish" / "mandarin" / "strawberry" / "quiz", x, y, width, height }` を指定します。既存の `decorations` 配列は互換用に受け付け、同じ座標の取得可能なアイテムとして扱います。`items` と併用する場合もIDを重複させないでください。穴も `holes: [{ id: "pit", x: 左端の座標, width: 穴の幅 }]` で直接指定でき、省略・空配列なら全面が床です。特定の岩だけ寸法などを調整したい場合は、変換結果の配列を加工してステージ定義へ渡せます。文字マップの行・列から生成するIDを使って対象を選びます。マップの行や列を挿入するとIDも変わるため、保存データなどの永続IDとしては扱いません。

直接指定した穴同士が重なる、または端で接している場合は、表示も衝突範囲もつながったひとつの穴として扱います。間に床がない場所へ土の縁だけを描くことはありません。

配置の変換は [stageMap.ts](../src/stageMap.ts)、岩の衝突・座標補正は [FixedObstacles.ts](../src/FixedObstacles.ts)、アイテムの表示・取得・座標補正は [StageItems.ts](../src/StageItems.ts)、穴の表示・床ボディ・座標補正は [StageGround.ts](../src/StageGround.ts) が担当します。物理座標を移し直してもマップから生成した元のステージ座標は変更せず、リセットで定義位置に戻します。

## アイテムの種類・効果を変更する

対応の正本は [items.ts](../src/items.ts) の `ITEM_TYPES` です。`type` は能力付き・得点のみ・クイズの区分、`assetKey` はmanifestの素材キー、`symbol` は文字マップの記号、`name` は通知に使う名前です。能力付きアイテムの `effect` は能力、`durationSeconds` は効果時間、`glow.color` は発光色、`glow.diameterScale` はキャラクターの大きさに対する円形発光の直径倍率です。持続時間と演出はここから種類ごとに変更できます。素材パス・実寸はmanifestを正とします。

種類を追加する場合は、素材をmanifestへ登録し、`ITEM_TYPES` へ区分・素材・重複しない記号を追加します。能力なしの種類の配点は [score.ts](../src/score.ts) の `SCORE_RULES.items` へ追加します。能力付きアイテムの共通配点・クイズの正誤配点・スコアの初期値と下限も同定義が正本です。上限は配置から自動計算します。クイズの問題文・4択・正解の元の添字・一文豆知識・出典URLは [quizData.ts](../src/quizData.ts) の `QUIZ_QUESTIONS` を編集します。`explanation` は回答後に表示する一文、`sourceUrl` は内容を確認するための公式情報のURLです。

問題は1問以上登録し、各問題の `id` は重複しない値にします。出題処理は登録数に応じて一巡を管理するので、問題を増やしても出題側の件数変更は不要です。問題数より多い `Q` を置いた場合も、全問を使い切るごとに新しい一巡から出題できます。

小物PNGは `assets/props/` から解決し、ステージで使う種類だけをPhaserへ読み込みます。新しい能力は [movement.ts](../src/movement.ts) に動作を追加します。取得済み状態と表示は `StageItems`、能力と残り時間は [powerUps.ts](../src/powerUps.ts)、出題・回答状態は [quiz.ts](../src/quiz.ts) に分けています。操作・停止・リセットの方針は [RUN](RUN.md) を参照してください。

取得・終了の文字表示時間、明滅を速める残り時間、通常時・警告開始時・終了直前の周期、発光の不透明度と中心高さは [feedback.ts](../src/feedback.ts) の `ITEM_FEEDBACK` が正本です。発光は [ItemFeedback.ts](../src/ItemFeedback.ts) がキャラクターの表示位置と渡された幅・高さに合わせて配置します。キャラクター固有の画像や輪郭には依存せず、左右反転でも円を反転させません。
