# 文字マップでステージの配置を編集する

配置の正本は [src/stage-maps/](../src/stage-maps/)、マスの大きさ・原点・ステージとマップの対応は [stages.ts](../src/stages.ts) です。現在のステージは [tea-river.txt](../src/stage-maps/tea-river.txt) を読み込みます。

## 記号と位置

| 記号 | 配置 |
|---|---|
| `.` または半角空白 | 何も置かない |
| `x` | 岩1個。表示・矩形当たり判定は1マス分 |
| `o` | tea画像の仮表示。衝突・取得・効果はなし |
| `=` | 地面の高さを表す基準線。最下行にだけ指定 |

`xxxxx` は5個の岩です。ひとつの画像やボディには結合しません。上の行に置くほど高い位置になり、同じ行の岩は上面の高さがそろいます。空中に置いた岩も固定され、落下しません。

マップは長方形にし、全行の文字数をそろえてください。最下行はすべて `=` にします。行を伸ばす場合は、ほかの行にも `.`、最下行にも `=` を追加します。前後の空行、UTF-8のBOM、Windowsの改行に対応しています。行の途中の空行や未対応の記号はエラーになります。

最下行の `=` 自体は地形ボディを生成せず、既存の反復地面の高さを基準にします。マップの左右端は移動の端にならず、配置は横方向へ反復しません。現在のプレイヤー開始位置は従来どおりなので、開始位置に岩が重ならないように配置します。

## 編集する

1. `tea-river.txt` をテキストエディターで開き、`.` を `x` / `o` に置き換えたり、上下左右へ移したりして保存します。等幅フォントだと位置を見比べやすくなります。
2. [RUN](RUN.md) の手順で開いた画面を確認します。開発サーバーでは保存したマップが反映され、シーンは開始位置へ戻ります。
3. ジャンプで次の段に届くこと、上面へ着地すること、側面・隣接する岩の継ぎ目で意図した動作になることを確認します。検証手順は [CHECKS](CHECKS.md) を参照してください。

マスの幅・高さを変える場合は、`stages.ts` の `STAGE_MAP_GRID.cellWidth` / `cellHeight` を編集します。岩の位置・表示寸法・当たり判定、teaの配置と表示枠が一緒に変わります。teaは表示枠内に縦横比を保って収めます。横方向の原点は `originX`、地面の基準は `groundY` です。通常のステージでは地面の正本である `WORLD.ground` を基準にします。

マスを大きくすると段差や距離も広がるため、変更後は改めてジャンプで届くか確認します。ジャンプの高さや速度の設定を、配置変更に合わせて自動で変えることはありません。

## 別のステージを作る

`src/stage-maps/` に別の `.txt` を保存し、`stages.ts` から `?raw` 付きで読み込みます。ステージ定義に `...parseStageMap(読み込んだ文字列, 設定)` を指定すると、`obstacles` と `decorations` が生成されます。ステージごとに設定を変える場合は、`{ ...STAGE_MAP_GRID, cellWidth: 希望の幅, cellHeight: 希望の高さ }` のように渡します。

既存の座標指定による `obstacles` / `decorations` 配列も使えます。特定の岩だけ寸法などを調整したい場合は、変換結果の配列を加工してステージ定義へ渡せます。文字マップの行・列から生成するIDを使って対象を選びます。マップの行や列を挿入するとIDも変わるため、保存データなどの永続IDとしては扱いません。

配置の変換は [stageMap.ts](../src/stageMap.ts)、岩の衝突・座標補正は [FixedObstacles.ts](../src/FixedObstacles.ts)、tea仮表示の座標補正は [StageDecorations.ts](../src/StageDecorations.ts) が担当します。物理座標を移し直してもマップから生成した元のステージ座標は変更せず、リセットで定義位置に戻します。
