# ききまる — 2Dゲーム画像素材 v2

「ベルフラワークス」のキャラクター「ききまる」の画像素材です。この文書は素材の仕様と組み込み制約だけを扱います。
ゲームの実装状況・今後の構想は [STATUS](../../docs/STATUS.md)、操作手順は [RUN](../../docs/RUN.md) を参照してください。

## 最初に

ZIPを**すべて展開**し、`preview.html` をブラウザで開いてください。外部ライブラリや通信を使わず、画像の組み立て、動作の切り替え、エプロンの色替え、左右反転を確認するための見本です。ゲーム本体ではありません。

`preview.png` は正面・右向き・喜びポーズを組み立てて確認した静止画です。
Agentの入口はプロジェクトルートの [AGENTS.md](../../AGENTS.md) です。
素材プレビュー内の配置データは制作時の見本です。現行の配置を変更する場合は `rig-layout.json` を正としてください。

## アニメーション方式

### 配置データの読み方

配置の数値・初期色は [rig-layout.json](rig-layout.json)、画像パス・実寸は [manifest.json](manifest.json) を正本とします。
配置座標はrigの `canvas` に定義されたローカル座標です。各ノードの `x/y` は画像左上、`w/h` は表示寸法、`pivot` は回転基準点の割合で、配列順が描画順です。

- 右向きの `far_arm` は胴体より奥、`near_arm` は胴体・エプロンより手前に描画します。
- 正面では両腕を胴体の後に描画します。通常は頭を腕より前、万歳時は腕を頭より前に描画します。
- 万歳の回転方向は腕の名前だけで決めず、肩のX座標で決めます。
- 左向きは右向き全体の反転で表現します。
- 見た目と物理ボディは分離し、腕振り・反転・透明余白で当たり判定を変えません。

### 動作の表現例

これは、完成済みの連番アニメーションではなく、**パーツを組み合わせて動かすカットアウト素材**です。胴体・頭・左右の腕・左右の足・エプロン・胸のマークを一つの親オブジェクトにまとめます。腕と足は同じ画像を複製し、必要に応じて反転します。

- 待機：全体の微小な上下運動。
- 走る：足の前後移動と小さな回転、逆方向の腕振り、胴体の上下運動。
- ジャンプ：移動はゲームの物理処理。見た目に伸縮・腕上げ・着地の煙を追加。
- 喜び：`head_happy` に切り替え、腕を上げ、繰り返し跳ねる。
- 驚き・被弾：`head_surprised` に切り替え、揺れや点滅をゲーム側で追加。

`preview.html` のジャンプは見た目の見本であり、物理計算や当たり判定ではありません。個別の頭はAI生成由来の小さな輪郭差があります。ゲームで表情を切り替えた際に必要なら位置・表示サイズを微調整してください。

## エプロンの色替え

`apron_tint.png` は白系・薄いグレーを基調とする独立画像です。ゲーム側でこのパーツだけに乗算系の色付けをします。初期色は `rig-layout.json` の `defaultApronColor` を参照します。`badge.png` は別に重ね、クリーム色と紫のマークを保ちます。胴体や親オブジェクト全体に色を付けないでください。

黒に近い色では陰影が見えにくくなります。中程度以上の明るさの色を使うと元の印象が残ります。強化の種類を色だけで伝えず、アイコンや表示文も併用する想定です。

## 地域・ステージ素材の扱い

食べ物は収集アイテムの**候補**で、産地や自治体との対応、強化内容は未確定です。えび・魚は一般化したイラストで、特定の生物種を正確に描いた資料ではありません。地域クイズの根拠として扱わないでください。

背景は静岡県中部を連想させる創作風景で、実在の場所を再現したものではありません。既存の `tea_river.png` はシームレス背景ではないので、そのまま横に反復すると継ぎ目が出ます。画面を覆う背景として固定するか、スクロール範囲を制限してください。背景に地面の当たり判定は含まれません。

追加の `tea_river_repeat_x.png` は、同一画像を反転・重ね合わせせず横に並べる用途で制作した、不透明な一枚絵です。上下方向の反復やレイヤー別の視差には対応していません。`previews/` は確認専用で、ゲームに読み込む背景ではありません。3枚連結画像の境界は x=1536 / 3072、等倍切り出し画像の境界は中央 x=384 にあります。

現行ゲームは `tea_river_repeat_x.png` を使用します。読み込み後に [RepeatingScenery.ts](../RepeatingScenery.ts) で右端の細い帯を左端へなめらかに重ねた描画用テクスチャを作り、境界の色差を抑えています。反復周期は元画像の幅から重ね幅を引いた長さです。元PNGと制作時の静止プレビューは変更しません。画像全体は縦横比を保って画面の高さに合わせ、遠景を地面よりゆっくり流します。

### ステージの背景を差し替える

1. `assets/backgrounds/` に不透明な横反復用PNG（例：`<風景名>_repeat_x.png`）を追加します。
2. `manifest.json` に固有の `key`、`path`、実際の `width` / `height`、`repeatX: true`、`repeatY: false` を登録します。
3. [stages.ts](../stages.ts) の `STAGES` にステージを追加し、`background.assetKey` にmanifestのキーを指定します。`scrollFactor` は地面に対する移動倍率（0なら固定）、`seamBlendPixels` は元画像上の重ね幅（0なら補正なし、補正する場合は2以上かつ画像幅の半分未満の整数）です。既定ステージは同ファイルの `DEFAULT_STAGE` で選びます。

シーンを開始・再起動する側から `{ stage: STAGES.対象 }` を渡すこともできます（例：`scene.start("walk", { stage: STAGES.teaRiver })`）。画像パスや寸法を `WalkScene.ts` に埋め込む必要はありません。新しい素材でも継ぎ目と地面付近の構図を確認してください。大きく異なる左右の構図を、重ね処理だけで自然につなぐことはできません。

制作・確認の到達点は [STATUS](../../docs/STATUS.md) を参照してください。

### ステージに固定障害物を配置する

通常の配置は [文字マップ編集ガイド](../../docs/STAGES.md) を参照してください。岩は `x`、お茶の仮表示は `o` で配置できます。以下は、個々の座標や寸法を直接指定する場合の仕様です。

[stages.ts](../stages.ts) のステージ定義に `obstacles` 配列を指定します。省略または空配列なら障害物を置きません。現在の種類は既存の `props/rock` を使う `rock` です。

各要素には、ステージ内で一意の `id`、`kind`、左上のステージ座標 `x` / `y`、表示と矩形当たり判定に共通の `width` / `height` を指定します。単位はゲーム内のピクセルで、負のX座標も使えます。地面に置く場合のY座標は `WORLD.ground - height` とします。岩の輪郭に沿った判定ではなく、指定した矩形の側面と平らな上面が衝突面です。

配列の座標は開始時のステージ座標です。[FixedObstacles.ts](../FixedObstacles.ts) が累積の座標補正量を保持し、表示・固定ボディ・物理エンジンの衝突検索位置を同時に更新します。リセットではこの補正量を戻し、同じオブジェクトを定義位置へ配置し直します。障害物は背景のようには反復しません。

新しい種類を追加する際は、素材をmanifestへ登録し、[obstacles.ts](../obstacles.ts) の種類と検証、`stages.ts` の種類と素材キーの対応・読み込む画像パターンを更新します。画像パスはmanifestを正とし、ステージの個々の配置へ複製しません。

足場や操作ボタン、クイズ本文、Resultの文字はゲーム側で描画する想定です。任意サイズに伸ばす地形タイルや完成したステージマップは今回の素材には含みません。

## 素材制作時の確認範囲

素材制作時に、28画像の読み込み情報、27画像のアルファ透過、切り出し位置、静止画での重なりを確認した記録です。これは現行ゲームの動作確認結果ではありません。

画像は画像生成機能で制作し、切り出し・PNG化・静止画での組み合わせ確認を行いました。
